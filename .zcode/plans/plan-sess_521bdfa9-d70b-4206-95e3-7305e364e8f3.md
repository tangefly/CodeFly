# 日程助手设计重构：固定安排成为一等公民

## Context（问题根因）

用户反馈：只有固定课程和会议时，日程助手无法生成日程表，必须补充科研任务。根因是设计上是纯"任务驱动"：

1. **硬性拦截**：`apps/server/src/schedule/tools.ts:1042-1058` — `plan_schedule`/`plan_replan` 在没有 todo/in_progress 且剩余时间>0 的任务时直接返回"没有需要排期的任务"，不生成任何计划。
2. **固定日程只是自由文本 memory**：课程表/会议存进 `class_schedule_constraint`、`fixed_meetings` 两条 memory，但调度器、渲染器、运行时上下文**都不读取** memory 的结构化 `data`；调度器（`scheduler.ts buildDayPools`）只扣除"属于任务的 block"。
3. **模型表达缺口**：`ScheduleBlock` 强制 `taskId`（无任务就没有 block），`ScheduleTaskInput` 无固定日程概念，系统提示词全程只讲"任务+估时"。

修复方案：引入一等公民实体 `ScheduleFixedEvent`（每周固定 / 一次性两类），贯穿协议→存储→调度→工具→渲染→面板；`plan_schedule` 支持零任务生成纯固定日程周表；现有两条 memory 自动迁移为固定安排。用户已确认完整改动（含面板 UI）。

## 改动清单

### 1. 协议层
- `packages/protocol/src/types.ts`：
  - 新增 `SCHEDULE_FIXED_EVENT_KINDS = ["weekly","once"]`、`ScheduleFixedEvent`（id, title, kind, weekday 1-7 / date YYYY-MM-DD 二选一, start, end, location, note, createdAt, updatedAt）、`ScheduleFixedEventInput`。
  - `SCHEDULE_TOOL_NAMES` 增加 `fixed_event_list`、`fixed_event_upsert`、`fixed_event_delete`。
  - `ScheduleOverview` 增加 `fixedEvents: ScheduleFixedEvent[]`。
- `packages/protocol/src/schemas.ts`（~240-332 附近，参照 memory/task schema）：新增 `scheduleFixedEventCreateSchema`、`scheduleFixedEventUpdateSchema`（校验 weekly→weekday、once→date、end>start）。

### 2. 存储层 `apps/server/src/schedule/store.ts`
- 新数据文件 `data/schedule/fixed-events.json`，照抄 memories/tasks 的 load/normalize/persist 模式（Map + atomicWriteFile 队列）。
- 方法：`listFixedEvents()`（按 weekday/date/start 排序）、`getFixedEvent`、`upsertFixedEvent`（新建需 title+kind+start+end+weekday/date）、`deleteFixedEvent`、`fixedEventsForDate(date)`（weekly 按 weekday、once 按 date）。
- `overview()` 返回 `fixedEvents`。
- **一次性迁移**（`init()` 内，幂等）：识别 memory `data.weekly`（`{day,start,end,title}`）与 `data.schedule`（`{Mon:[{start,end,loc}]…}`）两种已知结构，转为固定事件；转换后在源 memory 的 `data` 上写 `migratedFixedEvents: true` 并按 title+weekday+start 去重，避免重复。用户现有的课程表和会议会立即生效。
- `updateBlock` 的 `assertNoOverlap` 扩展：与当天固定事件重叠时报 `BLOCK_OVERLAP`。

### 3. 调度器 `apps/server/src/schedule/scheduler.ts`
- `SchedulerInput` 增加 `fixedEvents`；`buildDayPools` 每天扣除固定事件占用的区间（clamp 到工作时段，保留 GAP_MINUTES 缓冲，与现有 block 一致）。固定事件**不计入** `existingMinutes`（不占每日专注上限）。容量计算随之自动正确。

### 4. 工具层 `apps/server/src/schedule/tools.ts`
- 新增 3 个工具（定义+handler，view 用 `"fixed"`，风格与 memory_/task_ 一致）：`fixed_event_list`、`fixed_event_upsert`、`fixed_event_delete`。
- **核心：改掉 `runPlanner` 的拦截（1042-1058）**：`active.length === 0` 时——
  - 若目标周有固定事件：继续走 `applySchedule`（blocks 为空，写 planMeta/warnings）+ 渲染 PNG，返回"本周没有需要排期的科研任务，已生成仅含固定安排（课程/会议）的周表"+ 周表文本 + PNG 路径。
  - 若连固定事件也没有：返回指引性消息（提示可先登记固定安排或添加任务），不再是生硬报错。
- `generateSchedule` 调用传入 `fixedEvents`；更新 plan_schedule/plan_replan 的工具描述（说明固定日程会占用时段、零任务也可生成）。

### 5. 运行时上下文 `apps/server/src/schedule/service.ts`
- `runtimeContextMessage` 增加结构化固定事件行：`- Fixed events: N weekly · M one-off · 周一 08:00-09:35 课程（3-130）; 周一 16:00-17:30 线上会议A; …`（截断到 ~15 条）。模型每轮都能看到已登记的固定安排。
- `READ_ONLY_SCHEDULE_TOOLS` 加入 `fixed_event_list`。

### 6. 提示词 `apps/server/src/schedule/prompt.md`
- 新增「固定安排（课程与会议）」一节：用 `fixed_event_upsert` 登记固定课程/会议（weekly/once），不需要估时；**只有固定安排的一周也是合法计划，直接 `plan_schedule` 生成周表/PNG**；发现结构化的固定承诺类 memory 时先 `fixed_event_list` 查重再登记，不要反复向用户要科研任务。
- 相应调整 "First contact" 第 3 步与 "Planning" 一节，移除"必须先有任务"的隐含门槛。

### 7. 渲染 `apps/server/src/schedule/render.ts`
- `buildScheduleTable` 输入增加 `fixedEvents`；`ScheduleTableRow` 增加 `isFixed` + `fixedEventId`。固定事件作为行渲染在任务行之前（按当天最早开始时间排序），meta 列显示"固定 · 时长"与地点，样式区分（如灰蓝色标题 + 「固定」标记）。
- PNG 汇总条增加"固定 N 项"。邮件复用同一渲染，无需改 `email.ts`。

### 8. 路由 `apps/server/src/routes/schedule.ts`
- 新增 `POST /api/schedule/fixed-events`、`PATCH/DELETE /api/schedule/fixed-events/:id`（用协议层新 schema + audit `schedule.fixed_event.changed`，模式照抄 memories 路由）；overview 自动带出 fixedEvents。

### 9. Web 面板
- `apps/web/src/components/schedule/SchedulePanel.tsx`：
  - `WeekTable`：从 `overview.fixedEvents` 计算本周固定行（weekly 按 weekday、once 按 date），显示在任务行之上、带「固定」标记与地点——**plan 为 null 时也显示**，直接解决"看不到日程表"。
  - 新增「固定」tab：列表 + 新增/编辑对话框（标题、weekly/once、星期或日期、起止时间、地点、备注）+ 删除确认，模式照抄 MemoryEditor/TaskRow。
  - 空计划文案与汇总 chip 更新（显示固定安排数量）。
- `apps/web/src/lib/api.ts`（372 行附近的 schedule 客户端）+ `store.ts`：增加 fixed-events 的 api 方法与 store actions，照抄 memory 的现有模式。

### 10. 测试 `apps/server/test/`
- `schedule-store.test.ts`：固定事件 CRUD/持久化/重载；迁移把两种 memory 结构转成事件且二次 init 幂等；`updateBlock` 拒绝与固定事件重叠。
- `schedule-scheduler.test.ts`：固定事件正确扣除可用区间（如周一 08:00-09:35 课程后首个任务 ≥09:45）；不消耗专注上限；零任务调度不报错。
- `schedule-tools.test.ts`：零任务+固定事件时 `plan_schedule` 成功返回周表（不再拦截）；两者皆无时返回指引消息；`fixed_event_upsert` 参数校验。
- `schedule-render.test.ts`：表格含 isFixed 行且排在最前。
- `schedule-routes.test.ts`：overview 含 fixedEvents、CRUD 路由。
- `schedule-service.test.ts`：运行时上下文含固定事件行。
