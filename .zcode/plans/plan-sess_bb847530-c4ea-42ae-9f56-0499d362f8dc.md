# 过期日程完成确认机制

## Context

时间前进后，过去日期的 planned 块完成情况未知。现状：`plan_schedule`/`plan_replan` 在 `applySchedule` 内把过期 planned 块静默标为 `skipped`（工作量保留重排，不丢工作），但 (1) 模型看不到过期块——runtime context 只覆盖 today→+6，`getWindow` 过滤 `>= today`；(2) 从不主动询问用户，用户做了没说 → 重复排期；(3) 自动跳过无任何报告，模型无从转述。

目标（已与用户确认取舍）：**引导式、不拦截**——agent 在**规划/进度相关回合**主动检查过期块：先查任务记录，无法从记录判定的用 `ask_user_question` 询问，用 `block_update` 记录结果，然后才排期；排期结果中报告自动跳过数量。

**"过期未确认块"定义**：`status === "planned"` 且（`date < today` 或 `date === today && end <= 当前时刻`）。不改状态枚举、不改 protocol、不动 UI（这些块仍是普通 planned 块，只是被查询出来）。

## 改动

### 1. `apps/server/src/schedule/store.ts` — 新查询

新增 `listOverduePlannedBlocks(options?: { today?: string; nowMinutes?: number; limit?: number }): ScheduleBlock[]`：
- 遍历所有 plans（仿 `clearPlannedBlocks` 的扫描模式，store.ts:1625-1639），过滤 `planned` 且时间已过；
- 用现有 time.ts 工具：`compareDates`、`clockToMinutes`；默认值由 `todayInTimezone`/`nowMinutesInTimezone(preferences.timezone)` 计算；
- 按 date、start 升序，默认 limit 20。

### 2. `apps/server/src/schedule/service.ts` — runtime context 注入

`runtimeContextMessage`（service.ts:164-266）在 "This window's plan" 行后新增一行：
`- Overdue unconfirmed blocks: none` 或 `N 块（最早 MM-DD · 任务A×2 · 任务B×1）— 时间已过但未记录完成；规划前先确认（plan_get 可见明细与 block id）`
- 任务名从 `store.listTasks({ includeDone: true })` 建 map 关联（done 任务的 planned 块已被 `clearPlannedBlocks` 清掉，但保险起见仍可关联）。

### 3. `apps/server/src/schedule/tools.ts` — 两处

a) **planGet**（tools.ts:1370-1395）：`loadPlanView` 后调用新查询，非空则在 content 末尾追加：
```
过期待确认（时间已过但未记录完成，N 块 / 共 X 分钟）：
  · 2026-11-19 14:00-16:00 [block_xxx] 任务名 — note
```
格式仿 `formatPlan` 的块行（tools.ts:274-279），并放入 `meta.data.overdue`（UI 忽略未知字段，已确认安全）。

b) **runPlanner**（tools.ts:1431-1637）：在调用 `store.applySchedule`（tools.ts:1564）**之前**用新查询快照本次涉及任务（`included`）的过期块；applySchedule 后在 content（组装于 tools.ts:1589-1612）加一行报告：
- `date < today` 的块会被自动跳过 → `已将 N 个过期未记录块标记为跳过（约 M 分钟，工作量已保留并将重排）。如其中有些实际已完成，可用 block_update 改为 done，或用 task_upsert 补记实际用时。`
- `date === today` 已过时刻的块会被删除重排 → 并入计数，措辞涵盖（"已过期/已过时间"）。
- 不改 `applySchedule` 返回类型（保持 `SchedulePlan[]`，计数由前置快照得出，store 测试不受影响）。

### 4. `apps/server/src/schedule/prompt.md` — 新增一节

在 `# Planning` 之前加 `# Confirming overdue work`，并把这份数据补进 "First contact" 的 runtime context 清单（prompt.md:19）：
- 何时：仅规划/重排/汇报进度/问"还剩什么"的回合；注册课程、改偏好等无关请求不打扰。
- 步骤：
  1. **先查记录**：任务已 done → 无需处理；任务 `actualMinutes` 已覆盖该块（用户曾用 `task_upsert add_actual_minutes` 报过时间）→ `block_update status=done, actual_minutes=0`（避免重复记账，因为标记 done 默认会把块时长计入 actual）；
  2. **再问用户**：`ask_user_question` multi_select，每块一个选项（`MM-DD hh:mm-hh:mm 任务名`），并提供"其余都没做"选项；
  3. **记录**：完成 → `block_update status=done`（用户给了实际用时传 `actual_minutes`，没给则省略按块时长记账）；未完成 → `block_update status=skipped`（工作量保留重排）；
  4. 块已被重排删除 → 改用 `task_upsert add_actual_minutes` 补记。
- 排期后转述自动跳过报告，主动提出可纠正。
